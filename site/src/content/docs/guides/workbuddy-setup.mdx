## WorkBuddy 工作台核心设计原则

在智能媒体与生成式人工智能时代，使用 AI 的关键是建立安全受控的**工程工作区**，而不是无休止地在公共聊天网页中粘贴零散代码。

WorkBuddy 在本地生产中承担三大核心职能：
1. **工作区目录物理隔离**：严格通过 `Select Folder` 锁定在个人项目根目录，避免智能体访问无关系统文件。
2. **项目级技能（Skill）驱动**：将复杂的提示词与多步骤生产动作封装为 `.workbuddy/skills/` 下的标准化规程。
3. **知识库双向锚定**：通过 `@` 语法精准引用本地 Markdown 知识库与事实样本，实现数据不离开本地的安全协作。

## 初始环境配置步骤

### 1. 建立标准项目目录树

在个人电脑中新建课程独立工作区，标准骨架如下：

```text
my-course-repo/
├── .workbuddy/
│   └── skills/                  # 自定义技能目录
├── wiki/
│   ├── concepts/                # 理论与概念卡
│   ├── sources/                 # 一手采访与事实资料
│   ├── pitfalls/                # 避坑卡片
│   └── recipes/                 # 优质开篇与结构配方
├── briefs/                      # 内容执行简报
├── raw/                         # 原始未加工材料（只增不减）
└── audit-log.md                 # 人工终审核验日志
```

### 2. 安装项目级技能（Skill）

将技能文件夹直接存放在 `.workbuddy/skills/<skill-name>/` 下，每个技能包含一份 `SKILL.md`，头部声明 YAML 元数据：

```markdown
---
name: content-architect
description: 融媒体内容架构诊断与简报生成器。
---

# 技能执行正文...
```

### 3. 上下文精准引用与防幻觉规程

- 在对话或工单中，必须使用 `@wiki/sources/...` 显式引入事实材料。
- 禁止向智能体输入真实个人密码、手机号码、未脱敏学生花名册等敏感隐私。
- 每次模型生成结果必须由人工在 `audit-log.md` 记录核验结论并签署真实姓名。
