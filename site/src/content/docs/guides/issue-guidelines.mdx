## 为什么通过 GitHub Issue 提问？

在融媒体技术实训与 AI 编程过程中，遇到报错和瓶颈极其正常。但在微信或 QQ 私聊中零散截图提问存在严重的“信息丢失”与“知识孤岛”问题：
- 私聊提问往往只有一句“老师为什么跑不通”或一张模糊的手机拍照，缺少系统环境、完整报错日志与复现步骤，导致排查成本极高。
- 私聊答疑属于一次性消耗，同一类问题被十几个同学反复询问，造成极大的沟通内耗。

**通过 GitHub Issue 提问，是现代工程师与数字创作者的通用协作范式。**
每一个公开解决的 Issue，都会自动变成全班同学甚至下一届学弟学妹可以随时检索查阅的“避坑知识库”。

---

## 规范 Issue 的五大必备要素

一个能被快速响应并解决的 Issue，必须包含以下五项事实材料：

1. **环境上下文**：操作系统（Windows / macOS）、Python 版本、Node / Bun 版本、WorkBuddy 版本。
2. **当前意图与触发动作**：你刚才执行了什么具体命令，或点击了哪一个按钮。
3. **终端报错原文（Traceback）**：必须使用代码块复制纯文本日志，严禁只发半截手机拍照。
4. **自主排查尝试**：在提问前你尝试过哪些操作（如是否已检查文件路径、是否已重新安装依赖）。
5. **预期结果与实际表现的差距**：原本期望输出什么，实际卡在了哪里。

## Issue 提问标准模板

在提交 Issue 时，可直接复制以下 Markdown 模板：

```markdown
### 1. 基础环境
- 操作系统: [Windows 11 / macOS 15.0 / 其他]
- 工具链: [WorkBuddy / Python 3.11 / Bun 1.4 / 其他]
- 所属课程周次: [例如 第3周 账号诊断]

### 2. 进行了什么操作
我在执行以下命令或任务时触发了异常：
` ` `bash
python run.py --week 3
` ` `

### 3. 完整错误信息 (Traceback)
请直接粘贴终端红字报错全文：
` ` `text
Traceback (most recent call last):
  File "run.py", line 42, in <module>
    FileNotFoundError: [Errno 2] No such file or directory: 'raw/data.xlsx'
` ` `

### 4. 我已经尝试过的排查
1. 检查了 `raw/` 目录是否存在该文件，发现文件名拼写少了一个字符。
2. 尝试修改后依然报同样的错。

### 5. 预期表现
期望能够成功加载工作簿并解析出 11 行数据。
```
